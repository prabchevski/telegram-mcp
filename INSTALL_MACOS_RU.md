# Установка, обновление и диагностика

## Требования

- macOS с Homebrew и доступным пакетом TDLib **1.8.0**.
- Codex (приложение/CLI с локальным MCP) и/или Gemini CLI.
- Собственный Telegram-аккаунт, api_id и api_hash.
- Интернет для зависимостей и подключения к Telegram.

Пакет ищет TDLib в стандартных каталогах Homebrew для Apple Silicon и Intel.
Наличие этих путей не является проверкой всех моделей Mac и версий macOS.
Подтверждённые проверки выпуска перечислены в [отчёте](VERIFICATION_RU.md).

## Установить из архива

Получите ZIP и файл `.sha256` из одного доверенного источника. Откройте Terminal
в каталоге с ними и проверьте:

```sh
shasum -a 256 -c telegram-search-mcp-macos-v0.4.0.zip.sha256
```

Распакуйте ZIP. Внутри каталога `telegram-search-mcp-macos` запустите установщик
двойным щелчком либо выполните один из вариантов:

```sh
bash install-macos.command --clients codex
bash install-macos.command --clients gemini
bash install-macos.command --clients both
```

Установщик создаёт отдельный каталог версии внутри
`~/Applications/TelegramSearchMCP`, устанавливает зафиксированные Python-зависимости
и регистрирует выбранные клиенты. Копия исходников и среда каждой установки
сохраняются отдельно. Ссылка `current` указывает на последнюю установленную
и зарегистрированную версию; авторизация Telegram проверяется следующим шагом.
Наличие самих клиентов и их подключение установщик не проверяет.

Регистрация Codex использует имя `telegram_search`, Gemini — `telegram-search`.
Команды запуска очищают среду; в настройках клиентов разрешены ровно четыре инструмента. Клиентские
настройки не содержат Telegram-ключей. Перед изменением существующего файла рядом
создаётся приватная резервная копия; другие записи сохраняются. Для JSON Gemini
форматирование/комментарии могут измениться, исходный файл остаётся в резервной копии.

## Подготовить файлы без входа

```sh
bash install-macos.command --clients both --prepare-only
```

Эта команда устанавливает и регистрирует MCP, но не открывает интерактивную
авторизацию. Владелец аккаунта затем сам выполняет:

```sh
"$HOME/Applications/TelegramSearchMCP/current/tgsearch" auth
"$HOME/Applications/TelegramSearchMCP/current/tgsearch" doctor --connect
```

Установить программу и зависимости без изменения настроек клиентов:

```sh
bash install-macos.command --clients none --prepare-only
```

Для проверки установщика разработчиком предусмотрены `--install-dir`,
`--codex-config`, `--gemini-config`. Каждый путь должен быть абсолютным.
`--install-dir` задаёт корень со всеми версиями, а не каталог одной версии.
Если выбран другой корень, замените в командах этой инструкции
`$HOME/Applications/TelegramSearchMCP` на свой путь. Пути `--codex-config` и
`--gemini-config` нужно повторять при дальнейшей проверке или удалении
нестандартных регистраций: они не становятся настройкой по умолчанию.
`--skip-system-deps` допустим только вместе с `--prepare-only`: uv должен быть уже
установлен; полноценная работа всё равно требует TDLib.

## Добавить второй клиент позже

Повторите установщик с нужным `--clients`, либо используйте уже установленную версию:

```sh
"$HOME/Applications/TelegramSearchMCP/current/client-config" register --clients both
```

Перезапустите клиент. Отдельный вход в Telegram для второго клиента не нужен.

## Обновление версии 0.4 и следующих

1. Получите новый ZIP и проверьте его контрольную сумму.
2. Завершите текущие Telegram-запросы и закройте оба клиента.
3. Остановите общий сервис:

   ```sh
   "$HOME/Applications/TelegramSearchMCP/current/tgsearch" service stop
   ```

4. Запустите установщик нового архива с нужным `--clients`.
5. Перезапустите клиенты и выполните `doctor --connect`.

Старая папка программы сохраняется: работающие процессы не получают перезаписанную
среду Python. Существующий общий профиль и Keychain сохраняются. Если локальная проверка
`doctor` успешна, установщик пропускает повторный вход и выполняет
`doctor --connect`. Если профиль не настроен или проверка не проходит, начинается
авторизация. Пока старые
клиентские процессы открыты, они могут снова запустить прежний сервис: для полного
перехода перезапустите клиентов.

Для отката закройте клиенты, остановите сервис и выполните
`client-config register --clients both` из сохранённого каталога предыдущей
установки, затем перезапустите клиентов. Ссылка `current` сама
при такой ручной регистрации не меняется — используйте команды нужной версии
непосредственно. Профиль между разными форматами базы автоматически не конвертируется.

## Переход с Codex 0.2 или Gemini 0.3

Данные новой версии находятся в **TelegramSearchMCPShared**. Старые каталоги
TelegramSearchMCP и TelegramSearchMCPGemini и их записи Keychain остаются нетронутыми.
Новый вход создаст отдельное устройство Telegram. Не копируйте работающую базу.

1. Завершите старые Telegram-запросы в клиентах.
2. Запустите установщик с явной заменой распознанной старой записи:

   ```sh
   bash install-macos.command --clients both --replace-legacy
   ```

3. Войдите в собственный Telegram и перезапустите клиенты.

Флаг `--replace-legacy` разрешает замену только распознанных запускателей
Codex 0.2 / Gemini 0.3 с сохранённым исходным файлом проекта. Распознанные старые
записи под другими именами также заменяются одной стандартной записью.
Замена касается регистрации, а не старых данных и не процессов. Если запись
не распознана, установщик объяснит конфликт и сохранит её. Не удаляйте чужие MCP
записи вслепую: проверьте команду и сохранённую резервную копию.

## Диагностика

```sh
"$HOME/Applications/TelegramSearchMCP/current/tgsearch" --version
"$HOME/Applications/TelegramSearchMCP/current/tgsearch" doctor
"$HOME/Applications/TelegramSearchMCP/current/tgsearch" service status
"$HOME/Applications/TelegramSearchMCP/current/tgsearch" doctor --connect
"$HOME/Applications/TelegramSearchMCP/current/client-config" verify --clients codex
```

В последней команде укажите `gemini` для Gemini CLI или `both`, если зарегистрированы
оба клиента. Проверка `both` завершится ошибкой, если подключён только один.

`doctor` проверяет профиль, наличие ключей и библиотеки, не выводя сами ключи.
`doctor --connect` проверяет авторизацию через общий сервис. `service status`
показывает состояние сервиса, не открывая TDLib; `service start` запускает сервис
без входа в Telegram. `service stop` корректно завершает его; следующий запрос
снова запустит сервис.

В Codex CLI можно выполнить `codex mcp get telegram_search`. В Gemini CLI —
`gemini mcp list` и `/mcp`. Gemini проверяет локальные MCP только в доверенном
рабочем каталоге; настройте доверие к своему каталогу средствами клиента.

| Сообщение/ситуация | Что сделать |
| --- | --- |
| Setup incomplete / credentials missing | Выполнить `auth` в своём Terminal |
| Общий сервис уже работает при `auth` | Завершить запросы, выполнить `service stop`, повторить `auth` |
| Profile is in use | Не удалять tdlib.lock; проверить, не запущена ли авторизация/старая ручная копия; `service status` |
| Queue full / deadline / timeout | Дождаться остальных запросов и повторить узкий запрос; проверить интернет |
| Unsupported TDLib runtime | Проверить Homebrew TDLib 1.8.0; не устанавливать HEAD вместо стабильного пакета |
| MCP отсутствует в клиенте | Проверить регистрацию, выбранный клиент и перезапустить его |
| Не отображается медиа | Сначала запросить preview; отображение PDF/аудио зависит от клиента |
| Неподдерживаемый якорь контекста | Выбрать соседнее текстовое сообщение; голосовое может не содержать текста |

При обращении за помощью передавайте версию, текст ошибки и состояние сервиса.
Не присылайте историю, Keychain, базу TDLib, QR, api_hash, коды или пароли.

## Обновления приватного проекта

Скачанный ZIP устанавливается без авторизации GitHub. Для друзей без доступа к
репозиторию владелец передаёт новые ZIP и `.sha256` вручную. Автоматического доступа
к приватным исходникам или обновлениям архив не предоставляет.

Официальные справки: [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli),
[Gemini CLI MCP](https://geminicli.com/docs/tools/mcp-server/),
[Telegram API credentials](https://core.telegram.org/api/obtaining_api_id).
