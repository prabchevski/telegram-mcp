# Проверка выпуска 0.4.0

Дата: **15 сентября 2026 года**. Проверка выполнена в отдельной рабочей копии
на macOS с Apple Silicon; действующий Telegram-профиль не использовался.

## Подтверждено автоматически

**159 тестов прошли на Python 3.13**, без пропусков.

- Прежние операции поиска, сообщения, контекста и медиа; пределы и недоверенные
  метаданные, проверки путей, приватности и привязки профиля к аккаунту.
- Два настоящих MCP stdio-процесса с шестью параллельными вызовами: один общий
  тестовый сервис, не более одной одновременно выполняющейся операции.
- Шесть независимых процессов одновременно запускают один сервис; после закрытия
  MCP-клиентов сервис остаётся доступен следующей задаче.
- Отмена клиента, истечение срока ожидания, заполнение очереди, медленный клиент,
  корректная остановка и автоматическое завершение при простое.
- SIGTERM во время имитации нативной операции: блокировка сохраняется до завершения
  работы; принудительное падение отдельного тестового процесса и восстановление
  через старый сокет без удаления файла блокировки.
- Неподтверждённое закрытие TDLib сохраняет настоящую файловую блокировку; другой
  владелец её не получает. Ошибка нативной сессии завершает сервис, а не открывает
  новый TDLib-клиент поверх прежнего.
- Ограничения протокола, проверка UID и прав файлов, закрытый список операций;
  12 MiB медиа действительно переданы через локальный сокет.
- Регистрация обоих клиентов в отдельных временных настройках, сохранение других
  настроек, резервные копии, отказ при неизвестном конфликте, откат при второй
  неудачной записи, одновременные установщики, распознавание старых имён подключения.
- Установщик всегда выбирает управляемый uv Python, исключая системный Python и
  окружение проекта; проверены наличие интерпретатора и путь его загрузки.
- Настоящая установка с uv в отдельный каталог macOS, повторная установка с сохранением
  прежнего исполняемого файла, проверка и удаление временных подключений.
- Детерминированный архив, контрольные суммы, полный состав, запрет runtime/credentials
  и проверка соответствия wheel исходникам.

Telegram в проверках очереди заменён искусственным источником сообщений. Эти тесты
доказывают управление процессами/сессией и передачу данных, но не поиск в реальном
аккаунте или отображение каждого формата медиа внутри Codex/Gemini.

## Проверено живьём без авторизации аккаунта

- Настоящий MCP-процесс: stdio handshake и обнаружение ровно четырёх инструментов.
- Установленная нативная TDLib дважды создала клиент и подтвердила закрытие.
  Параметры базы, API credentials и аккаунт ей не передавались.
- Установка и обновление из реально собранного ZIP; затем запуск MCP из установленной
  копии и обнаружение четырёх инструментов по stdio.
- Контрольные суммы личных настроек Codex и Gemini до/после работы совпадают.
  Работающая прежняя установка и профиль не переключались.

Воспроизводимые команды:

```sh
uv sync --frozen --group dev
uv run --frozen pytest
bash scripts/build-macos-archive.sh
uv build --wheel --out-dir dist
uv run --frozen python -I scripts/release.py verify-wheel dist/telegram_search_mcp-0.4.0-py3-none-any.whl
uv run --frozen python -I scripts/smoke-install-macos.py dist/telegram-search-mcp-macos-v0.4.0.zip
# Дополнительно, при установленной Homebrew TDLib; без входа и базы:
uv run --frozen python -I scripts/smoke-native-lifecycle.py
```

CI настроен на Linux/macOS и Python 3.12/3.14, затем на сборку и реальную
изолированную установку архива на macOS. Результаты конкретных запусков находятся
в **Actions** приватного репозитория.

## Требуется пользовательская авторизация/установленный клиент

- Новый вход владельца в собственный Telegram для профиля 0.4.
- Поиск и получение медиа через живой авторизованный аккаунт в новой версии.
- Отображение результатов внутри установленного Gemini CLI; Gemini CLI на тестовом
  Mac отсутствует. Проверены формат его регистрации и стандартный протокол MCP.
- Финальная проверка новой регистрации в личных Codex/Gemini после переключения.
  Старый рабочий Codex сохранён, поэтому проверка нового Telegram-поиска в нём не заявляется.
- Работа на физическом Intel Mac: предусмотрены стандартные пути, но отдельного
  физического устройства для проверки не было.

Исправление повторяющейся блокировки реализовано и проверено на изолированной
конкуренции. Оно начнёт действовать в личной установке после входа в новую версию
и переключения регистрации клиентов. Старые активные процессы не останавливались.
