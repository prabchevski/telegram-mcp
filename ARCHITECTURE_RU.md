# Архитектура и границы доступа

## Общая сессия

```text
Codex, задача 1 ── MCP stdio ─┐
Codex, задача 2 ── MCP stdio ─┼── локальный Unix socket ── очередь ── TDLib ── Telegram
Gemini CLI     ── MCP stdio ─┘                         один владелец профиля
```

MCP-сервер — небольшой посредник. Он запускает общий фоновый сервис при первом
обращении. Список инструментов доступен ещё до авторизации Telegram.
Сервис обслуживает один профиль текущего пользователя macOS; другие пользователи
и профили изолированы. Отдельная блокировка исключает одновременный старт нескольких
сервисов. Защитная блокировка `tdlib.lock` продолжает охранять базу TDLib.

Сервис выполняет только фиксированный набор запросов: четыре операции чтения и
локальную диагностику/остановку. Произвольный метод TDLib, имя Python-функции,
путь к медиа или команда для выполнения через канал не принимаются.

## Локальный канал

Используется Unix socket в коротком приватном каталоге текущего пользователя.
Это не HTTP-сервер: порт в сети не открывается. Каталоги имеют права 0700,
файлы соединения доступны владельцу. Проверяются владелец, символьные ссылки и
учётные данные подключившегося процесса. Протокол ограничивает размер сообщений,
параметры и длину очереди. Запросы и содержимое Telegram не записываются в журнал.

Граница доверия — **учётная запись macOS**. Другая программа, работающая от вашего
имени, обладает теми же локальными правами. Это не средство изоляции от вредоносного
ПО, уже запущенного в вашей учётной записи. Клиент ИИ получает те результаты Telegram,
которые возвращены ему инструментами, и обрабатывает их по собственным правилам.

Запуск клиентов очищает внешнюю среду, использует абсолютный путь Python и режим
`-I`. Пути к TDLib фиксированы для Homebrew Apple Silicon/Intel. Переменные проекта
не могут выбрать другую базу через `TGSEARCH_DATA_DIR` или библиотеку через
`TDJSON_LIBRARY`. Секреты не помещаются в MCP-конфигурацию.

## Таймауты, очередь и завершение

По умолчанию очередь содержит до 16 ожидающих запросов и одну выполняющуюся
операцию. На запрос отводится до 120 секунд с учётом очереди; конфигурации клиентов
оставляют 150 секунд с запасом на запуск. После 10 минут без чтений сервис
завершается. Локальный канал ограничен 40 соединениями и сообщением ответа 18 MiB
(медиа передаются в base64).

Отмена ожидания клиентом не означает, что нативная операция TDLib уже остановилась.
Сервис дожидается фактического завершения выполняющейся операции перед следующей.
Просроченные ожидающие запросы не должны задерживать новые чтения; переполненная
очередь возвращает понятную ошибку. При разрыве соединения клиент не пытается
бесконечно повторять запросы.

`tgsearch service stop` прекращает приём новых операций, завершает текущую работу
и закрывает сессию без выхода из Telegram. После остановки следующий запрос снова
запускает сервис. При обычном завершении и сигнале остановки база освобождается
корректно; после аварийного завершения блокировки освобождает операционная система.
Ни установщик, ни диагностические команды не удаляют `tdlib.lock` и не завершают
посторонние процессы. После простоя сервис освобождает ресурсы автоматически.

Для интерактивного `auth` используется та же блокировка владельца сервиса —
credentials не меняются одновременно с активной сессией. Если сервис работает,
сначала завершите запросы клиентов и выполните `service stop`.

## Данные и совместимость

| Область | Поведение 0.4 |
| --- | --- |
| Данные | `~/Library/Application Support/TelegramSearchMCPShared/profiles/default` |
| Keychain service | `local.unofficial-telegram-search-mcp-shared` |
| Учётные данные | `default:api_hash`, `default:database_key`; только локальный Keychain |
| Старые Codex/Gemini данные | Не читаются и не копируются автоматически |
| Авторизация | Собственные api_id/api_hash, QR, при необходимости код и 2FA в Terminal |
| Медиа | Текстовые и структурированные метаданные для обоих клиентов |
| Полное изображение | Дополнительный `_meta` с подсказкой Codex `original` |
| Передача | Preview ≤2 MiB, full ≤12 MiB; способность клиента отобразить формат может отличаться |
| TDLib | Схема и версия 1.8.0; неизвестная версия отклоняется |

Профиль связывается с одним Telegram-аккаунтом; несовпадение аккаунта отклоняется.
Автоматический перенос старого профиля исключён из этого выпуска: нельзя безопасно
копировать открытую базу или угадывать, какой из двух аккаунтов пользователь хочет
сделать общим. Повторный вход создаёт отдельное устройство Telegram.

## Ограничения

Полнотекстовый поиск зависит от доступности истории в Telegram. Сообщения без
поддерживаемого текста могут не подходить как якорь контекста. Видео передаётся как
миниатюра; приложение не делает массовую выгрузку истории. Медиаданные кешируются
TDLib локально в профиле. Ограничение чтения относится к операциям Telegram:
авторизация, локальная база, кеш и настройки установки естественно изменяются.
